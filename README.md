اپ اندرویدی React Native + Expo + TypeScript برای ایجاد، ویرایش و انتشار نوشته‌های وردپرس از طریق **WordPress REST API** (بدون WebView پیشخوان و بدون افزونهٔ اختصاصی).

> **وضعیت: مراحل ۱ و ۲ از ۶ نوشته شده (اتصال امن، WordPressClient، فهرست/جست‌وجو/فیلتر نوشته‌ها). ساخت و ویرایش نوشته، ویرایشگر، رسانه و انتشار هنوز وجود ندارد. APK ساخته نشده است.**

## چه چیزی واقعاً بررسی شده؟

در محیطی که این کد نوشته شد **دسترسی شبکه نبود**، پس `npm install`، `expo install`، Jest، `expo start` و ساخت APK **اجرا نشده‌اند**.

اجراشده و تأییدشده:
- `tsc` در حالت strict روی ماژول‌های خالص (`src/services`، `src/utils`، `src/storage/session.ts`، `src/features/auth/validation.ts`) و تست‌ها: بدون خطا.
- ۸۰ تست (Jest-syntax) با یک runner ساده‌ی `node:assert` (`npm run verify:offline`): **۸۰/۸۰ موفق**.

اجرا/تأیید **نشده**: typecheck فایل‌های وابسته به Expo/React Native (`app/`، کامپوننت‌ها، استورها، `ConnectScreen`)، `npm test` با jest-expo، lint، رفتار RTL و فونت روی دستگاه، نصب `@expo-google-fonts/vazirmatn`، پیکربندی ESLint. ممکن است هنگام اولین نصب خطاهای کوچک نسخه/تایپ ظاهر شود.

## نصب

```bash
./setup.sh            # expo@latest + expo install برای نسخه‌های سازگار با SDK
npm run typecheck
npm test
npx expo start --android
```

نسخهٔ وابستگی‌ها عمداً در `package.json` حدس زده نشده؛ `expo install` آن‌ها را مطابق SDK انتخاب می‌کند.

### Expo Go یا development build؟
مرحلهٔ ۱ فقط از ماژول‌های موجود در Expo Go استفاده می‌کند (SecureStore، Router، فونت). ویرایشگر rich text (WebView) و برخی ماژول‌های بعدی ممکن است development build بخواهند؛ در همان مراحل مستند می‌شود. ساخت: `eas build -p android --profile development`.

### RTL
در اولین اجرا ممکن است پیام «برنامه را ببندید و دوباره باز کنید» دیده شود (محدودیت اندروید در تغییر جهت). پس از آن RTL پایدار است.

## ساخت Application Password
پیشخوان وردپرس ← کاربران ← پروفایل ← Application Passwords ← نام بنویسید ← افزودن ← رمز را کپی کنید. فاصله‌ها اشکالی ندارند. از رمز اصلی حساب استفاده نکنید. سایت باید HTTPS داشته باشد.

## اتصال و امنیت (آنچه پیاده شده)
- فقط HTTPS؛ http فقط در `__DEV__` با `EXPO_PUBLIC_ALLOW_INSECURE_HTTP=true`.
- رمز فقط در SecureStore، جدا از پروفایل سایت؛ در SQLite/AsyncStorage/لاگ ذخیره نمی‌شود. `JSON.stringify(client)` رمز ندارد.
- `Authorization` فقط به origin سایت ارسال می‌شود. ریدایرکت‌ها دستی دنبال می‌شوند و هر hop به origin دیگر رد می‌شود؛ ریدایرکتی که خود پلتفرم دنبال کرده باشد هم شناسایی و خطا داده می‌شود. اگر سایت به دامنهٔ دیگری (مثلاً www) منتقل شود، اتصال متوقف و آدرس جدید پیشنهاد می‌شود تا کاربر تأیید کند.
- کوکی ارسال نمی‌شود (`credentials: 'omit'`).
- کشف API: `/wp-json/` ← `/index.php/wp-json/` ← `/?rest_route=/` یا آدرس پایهٔ دستی (روی همان دامنه). زیرپوشه پشتیبانی می‌شود.
- retry خودکار فقط برای GET و خطاهای گذرا؛ POST/DELETE هرگز تکرار نمی‌شوند.
- ارسال تکراری فرم با `singleFlight` مهار شده.

### خطاهای رایج
| نشانه | علت محتمل |
|---|---|
| «نام کاربری یا Application Password درست نیست» | رمز اشتباه، یا Application Passwords غیرفعال (HTTP/افزونهٔ امنیتی) |
| «REST API در دسترس نیست» | پیوندهای یکتا روی «ساده» یا غیرفعال‌شدن API؛ آدرس پایه را دستی وارد کنید |
| «مسدود شد» | فایروال/افزونهٔ امنیتی (پاسخ 403/406 غیر JSON) |
| «اتصال برقرار نشد» | اینترنت، DNS یا گواهی HTTPS نامعتبر — React Native این‌ها را از هم تفکیک نمی‌کند |

## محدودیت‌های شناخته‌شده (فعلی)
- ربات‌های امنیتی/CDN ممکن است درخواست‌های اپ را مسدود کنند.
- خطای گواهی نامعتبر با خطای شبکه قابل تفکیک نیست.
- رفتار `redirect: 'manual'` در RN اندروید ممکن است متفاوت باشد؛ برای همین بررسی دوم روی `response.url` هم وجود دارد. روی دستگاه واقعی تست شود.
- SQLite عادی رمزنگاری‌شده نیست (از مرحلهٔ ۳ مهم می‌شود).
- نمایش آمار بازدید/فروش عمداً وجود ندارد؛ REST API استاندارد آن را ارائه نمی‌دهد.

## مرحلهٔ ۲: رفتار فهرست نوشته‌ها
- infinite scroll (۲۰ مورد در هر صفحه)، pull-to-refresh، جست‌وجو با debounce ۴۰۰ms.
- فیلتر وضعیت: همه (بدون زباله‌دان)، منتشرشده، پیش‌نویس، در انتظار بررسی، زمان‌بندی‌شده، خصوصی (فقط با مجوز `read_private_posts`)، زباله‌دان.
- فیلتر دسته‌بندی با دریافت تدریجی (۱۰۰ مورد در هر صفحه) و نمایش سلسله‌مراتب؛ مرتب‌سازی بر اساس تاریخ ایجاد یا ویرایش.
- انتقال به زباله‌دان با تأیید و `force=false` (حذف دائمی وجود ندارد). بازیابی فقط `status=draft` می‌فرستد تا نوشته‌ای ناخواسته منتشر نشود.
- پیام موفقیت/به‌روزرسانی فهرست فقط پس از تأیید سرور؛ خطاها با پیام فارسی.
- صفحهٔ خارج از محدوده (خطای 400 وردپرس) به‌عنوان «پایان فهرست» تلقی می‌شود.
- نمایش پیش‌نویس‌های دیگران به مجوزهای وردپرس بستگی دارد؛ سرور تصمیم نهایی را می‌گیرد و اپ مجوز را دور نمی‌زند.
- فرض: TanStack Query v5 (`initialPageParam`)؛ اگر `expo install`/npm نسخهٔ دیگری نصب کرد، تایپ‌ها را بررسی کنید.

## ساخت APK
APK در این محیط ساخته **نشد** (بدون شبکه و بدون حساب Expo). روی یک ماشین دارای اینترنت:

```bash
./scripts/build-apk.sh
```
یا مرحله‌به‌مرحله: `./setup.sh` ← `npm run typecheck && npm test` ← `npx eas-cli login` ← `npx eas-cli build:configure` ← `npx eas-cli build -p android --profile preview`.
AAB: `--profile production`. فقط پس از دیدن لینک دانلود در خروجی EAS می‌توان گفت APK ساخته شده است.
